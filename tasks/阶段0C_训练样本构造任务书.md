# 阶段 0C：训练样本构造器

版本：v1；布置日期：2026-11-11。状态：已布置，待用户组织实现并提交 review。

## 目标与范围

把文档级训练/验证划分、固定字符编码器和窗口构造接起来，产出可追溯的 x/y 样本。最终作业的预训练需要同类数据准备逻辑；本次仍用字符 token 和 Python 列表，不引入模型训练、PyTorch DataLoader、BPE、padding、EOS 或 GPU。

建议目录：`/Users/lcf/llm/learning/stage00_dataset/`。复用 `learning/stage00_char_codec/tokenizer.py` 中的 CharTokenizer，不复制改写一套编码器。导入组织方式自行选择，README 说明运行方式即可。

预计主动投入：设计和手算 20–30 分钟；组织 agent 开发、检查和读代码 60–90 分钟；准备提交和复盘 20–30 分钟。

## 输入与划分

输入三部分：固定词表、正整数 T、包含 train/val 两组完整文档的数据文件。

每个文档有唯一字符串 id 和字符串 text。两组由你在文件中明确指定，不必实现随机比例划分。这样划分先于窗口生成，而且能够重复运行得到相同结果。可用 JSON，例如：

```json
{
  "train": [{"id": "A", "text": "春风吹过山河"}],
  "val": [{"id": "B", "text": "山河春风"}]
}
```

公开示例词表：春=0、风=1、吹=2、过=3、山=4、河=5。两组共用同一个固定 tokenizer，处理期间不新增或改动编号。

校验：T 必须为正整数（拒绝布尔值）；id 为非空字符串且整个输入中唯一，尤其不能同时在 train/val 中出现；text 必须为字符串。空文档和空分组允许，按下面规则产生零个样本。两组有相同词语不等于泄漏；本期按文档 id 检查归属，不要求实现内容去重，也不把 id 不同等同于现实中一定没有重复内容。

## 样本构造规则

1. 每个文档单独编码、单独切窗口，绝不拼接两个文档。
2. 窗口输入长度为 T。起点从下标 0 开始，每次加 1（步长固定为 1）。本次要枚举所有合法起点，不要求随机采样或可配置步长。
3. 每个样本需要本篇文档中连续 T+1 个 token；x 与 y 均长 T，y 相对 x 在原文中后移一位。
4. 不补齐末尾，不借用下一篇文档，不添加特殊 token。不能取得完整 T+1 个 token 的起点直接跳过。长度 N 的文档在步长 1 时产生 max(0, N−T) 个样本。
5. 未知字符沿用 0B 的明确报错策略，消息应说明文档 id 及未知字符；训练或验证文档都适用，不静默删字符/删文档，不自动扩词表。先编码完整文档，再判断是否够长。
6. 保留输入文档顺序，各篇内部按起点递增排列。同一输入和配置应得到一致输出。

每条输出至少包含 doc_id、start、x、y；start 是该文档内从 0 开始的 token 下标。公开样本：

```json
{"doc_id": "A", "start": 0, "x": [0, 1, 2], "y": [1, 2, 3]}
```

训练样本只能来自 train 文档，验证样本只能来自 val 文档。

## 接口与交付产物

划分成两个可单独调用的层次，名称可自行决定：

- 单文档窗口构造：给 token 编号列表和 T，返回该文档的合法窗口及起点；不负责随机划分或文件保存。
- 数据准备入口：读取已划分文档，校验、复用 tokenizer、逐文档构造窗口，再分别保存训练/验证结果。

提交代码、断言检查脚本、示例数据/词表和 README。运行数据准备入口后产生：

- train_samples.json 和 val_samples.json（各自为样本列表）。
- metadata.json：至少记录 T、步长 1、实际词表映射、train/val 文档 id，以及各文档的 token 数和样本数。这样能查清零样本文档和样本来源。

输出位置可配置或由 README 明确指定；反复运行不能把旧样本追加进新结果。无需复杂 CLI、日志框架或文件格式设计。

## 工程验收

提供实际运行命令和断言结果；不能仅打印一串样本说“成功”。至少覆盖：

1. 手算两个不同起点的完整 x/y，与程序逐项比较；不能只检查长度或 x[1:]==y[:-1]，这不足以检查完整标签是否正确。
2. 公开例子 T=3：训练 A 有 3 个样本，验证 B 有 1 个样本；验证末尾合法起点没有漏掉。
3. 文档长度为 0、T−1、T、T+1 时，样本数符合规则；另测 T=1。
4. 每个样本的长度、起点和内容都能回溯到对应的原文；用含重复字符、空格与换行的新文本检查（为这些字符提供合法固定词表）。
5. 两篇各自不足 T+1 个 token 的文档，即使合起来够长，也不能拼成样本。同属训练组时也不能跨文档。
6. 重复文档 id（包括跨组重复）、非法 T 被拒绝；验证样本不进入训练输出。
7. 训练或验证文档包含未知字符都明确报错，词表保持不变。
8. 保存结果再读取后与内存样本相同；相同输入重复运行结果一致，metadata 数量与输出吻合。

本期按已给出的范围验收，不加入未讲的 BPE、batch、损失或分布式数据处理要求。
