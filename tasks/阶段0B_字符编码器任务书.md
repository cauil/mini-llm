任务版本：v1。状态：已布置，待用户提交；理解验收未完成。

## 这次要做什么

把已经学过的“文字 ↔ 编号”做成可重复使用的小模块。完成后应能解释：token、词表、encode/decode、为何同一模型必须使用同一份编号规则，以及为什么词表需要和编码数据一起保存。

本次每个 Python 字符作为一个 token。编号只是身份标识，不表示字符的大小、相似度或重要性。此模块还不是语言模型，不会预测下一个字符。

范围：固定词表、编码、解码、保存与加载。本次不要求 PyTorch、BPE、训练、窗口、数据划分或 UNK token。后续 0C 再做训练样本。

预计投入：理解和方案 15–25 分钟；组织 agent 实现与检查 30–60 分钟；阅读和整理提交 20–30 分钟。按理解情况调整。

## 输入输出示例

指定词表：`猫=0、吃=1、鱼=2、肉=3`。

- encode("鱼吃肉") → [2,1,3]
- decode([3,1,2]) → "肉吃鱼"
- encode("") → []；decode([]) → ""

这些是公开检查示例，不能把程序写成只识别这些句子。

## 功能与约束

建议在 `/Users/lcf/llm/learning/stage00_char_codec_submission/` 中提交。保留已有演示目录；可参考它并说明参考范围，不必为证明学习机械重写。

接口名称可以调整，但行为必须满足：

| 功能 | 输入 | 输出或行为 |
|---|---|---|
| 创建编码器 | 字符到编号的词表 | 后续各操作共用同一份映射 |
| encode(text) | 字符串 | 按原顺序输出整数列表，保留重复字符 |
| decode(ids) | 整数列表 | 按原顺序恢复字符串 |
| save(path) | 文件路径 | 保存词表，格式可用 JSON |
| load(path) | 已保存的词表文件 | 恢复可用于 encode/decode 的编码器 |

规则：

1. 词表由调用方提供；本次不要求从语料自动生成。各 key 是一个 Python 字符，编号为互不重复的整数，范围为 0 到 V−1，V 为词表大小。仅需支持非空词表；非法词表须报错。
2. 编码和解码期间不能重新编号、自动添加字符或更改词表。调用方后续修改原始字典也不能悄悄改变已创建编码器的行为。
3. 保留顺序、重复次数、空格和换行；不要自动 strip、排序或去重输入文本。
4. 本期使用明确的“拒绝未知输入”规则：出现词表外字符或无效编号时抛出异常，消息指出问题值。不能静默跳过或换成已有字符；异常类型自选并写在说明中。UNK 的策略以后再学。
5. 保存、加载必须保持字符与编号的对应关系；加载之后同样检查词表有效性。
6. Python 标准库即可，不使用现成 tokenizer 库。没有模型权重或 GPU 要求。

## 工程验收

提交可运行的检查脚本，使用断言判断正确性，不仅打印“成功”。至少覆盖：

- 公开示例和你自己手算的一个新例子。
- 重复字符与空文本。
- 包含空格、换行的文本：先提供包含这些字符的词表，再检查原样还原。
- 对词表覆盖的文本，decode(encode(text)) == text。
- 保存后重新加载：词表、编码和解码结果与原实例一致。
- 未知字符、负编号、越界编号，以及重复编号或不连续编号的词表均被拒绝。
- 两段文本先后编码时，词表保持不变；调用方修改原始字典不会影响编码器。

只做往返检查不够：编码与解码可能一起用错编号，却仍能还原文本。因此还要对照固定词表检查具体输出编号。
